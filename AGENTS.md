# AGENTS.md

## Project overview

The public Kotlin Swift Export sample. It shows how Kotlin Multiplatform code is exported to Swift with the `export.swift {}` DSL and the Swift package export from Kotlin 2.5.0. People read it to learn Swift Export, so code must be correct, small and easy to follow. `README.md` explains the DSL and every feature the sample covers.

- `shared/` - The umbrella Kotlin module, exported as the `Shared` Swift module. See `shared/AGENTS.md`.
- `module-a/` to `module-d/` - Kotlin libraries that show how dependencies are exported (library-configured, consumer-configured, `EXPOSED`, `HIDDEN`).
- `appleApp/` - The SwiftUI app for iOS and macOS, using `embedSwiftExportForXcode`. See `appleApp/AGENTS.md`.
- `spm-consumer/` - A Swift package that consumes the exported package. Its Swift Testing tests are the main feature tests.
- `shared/SwiftPackage/` - Generated by the export tasks and git-ignored. Never edit it.

## Setup

- JDK 21 and Xcode 16 or later (the sample is developed with Xcode 27). Gradle comes from the wrapper.
- Use the versions in `gradle/libs.versions.toml`. Ask before adding a dependency, a Kotlin target or a new Gradle module.

## Build and test commands

- Export the Swift package: `./gradlew :shared:exportDebugSwiftPackage`
- Feature tests (macOS): `swift test --package-path spm-consumer`
- Consumer executable: `swift run --package-path spm-consumer`
- App tests on macOS: `xcodebuild test -project appleApp/appleApp.xcodeproj -scheme appleApp -destination 'platform=macOS,arch=arm64'`
- App tests on iOS: `xcodebuild test -project appleApp/appleApp.xcodeproj -scheme appleApp -destination 'platform=iOS Simulator,name=<name>'`. List simulators with `xcrun simctl list devices available`.

`swift test` uses the package from the last export, so export again after every Kotlin change. The Xcode build runs Gradle itself. A Kotlin API change needs all of the commands above.

## Adding a Swift Export feature

1. Add the Kotlin declarations to the matching topic file in `shared/`.
2. Read the generated Swift signature in `shared/SwiftPackage/Debug/Sources/<Module>/<Module>.swift` before writing Swift against it. Argument labels, optionality and namespaces are easy to guess wrong.
3. Test it in `spm-consumer/Tests/SwiftExportTests/` and in `appleApp/Tests/Tests.swift`.
4. If it is visible in a UI, add a row to `appleApp/appleApp/ContentView.swift`.
5. Update the feature table in `README.md`, and the known limitations if there is one.

## Swift Export pitfalls

- The sample targets Kotlin 2.5.0-Beta2. A feature on Kotlin `master` may not exist in that version yet.
- Swift Export is Beta, but its Gradle DSL is still marked `@ExperimentalSwiftExportDsl`, and Gradle warns without `@OptIn(ExperimentalSwiftExportDsl::class)`. Keep the opt-in in build scripts, even though the Kotlin docs examples leave it out.
- Kotlin can't call Swift-only APIs. Declare a function type or interface in Kotlin and let Swift implement it (see `FunctionTypes.kt`).
- Swift package export can't be combined with `swiftPMDependencies {}` in 2.5.0. Support is planned for 2.5.20.
- A Swift class that implements a Kotlin interface must inherit from an exported Kotlin class, because `KotlinBase` can't be instantiated from Swift (KT-88251).
- Passing a Swift dictionary to a Kotlin `Any` parameter crashes with SIGSEGV in 2.5.0-Beta2.
- Declarations that need an opt-in are Swift SPI: `@_spi(<annotation FQN with $ instead of dots>) import Shared`.

## Code style

- Comments and docs are short and plain. Say what Swift sees, not how impressive it is.
- Every claim in `README.md` must be something the sample shows or a test checks. Keep it in sync with the code.

## Commits and pull requests

- Small, focused commits with a short imperative subject, for example "Add macOS destination to the Xcode app".
- CI (`.github/workflows/build.yml`) builds the app and its XCTests for the iOS simulator and macOS without running them, and runs `swift test` and `swift run` in `spm-consumer`. Run the XCTests locally before opening a pull request.

## Security considerations

- Never commit credentials. Leave `TEAM_ID` in `appleApp/Configuration/Config.xcconfig` empty.
- CI publishes Gradle build scans to scans.gradle.com, where they are public. Don't print secrets or private paths in Gradle output.
